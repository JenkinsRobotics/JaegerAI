# Canonical default-lead journal qualification, 2026-11-08

## Boundary

Fresh immediate and queued foreground admissions share the existing execution
resolver. Only an exact, enabled, persisted canonical `native:jaeger` native lead
whose assignment is already home/pinned/route_checked receives `_owner_agent` (`id`, `kind`, `role`, `disabled`) in execution JSON.
The existing client-choice digest remains unchanged. Journal identity already
binds the complete immutable execution JSON. Historical rows are never changed.
Caller-supplied markers are not execution input keys and cannot establish identity.
Subordinate requests and explicit options retain their existing admission shape.

Registry authority lookup uses the existing registry owner with a read-only
mode that constructs the exact validated persisted canonical record. Duplicate
catalog entries cannot shadow that authority. It neither seeds agents nor substitutes instance discovery for a
missing/deleted/corrupt persisted canonical entry. Invalid role/kind records are
not normalized into authority. Unknown assigned agents never become unassigned
journal controls. The ordinary UI registry/home bootstrap remains separate.

Agent identity is checked before agent-specific dispatch setup, native binding,
all-run effect qualification, sealing and receipt reads/recovery. Session
assignment, role, kind, disabled state, missing entries and corrupt registry data
fail closed. The existing lease/token, admitted grant, native ownership, all-run
settlement, atomic TaskCard cancellation/completion and projection gates remain.
Cancellation signaling is not blocked by identity drift; its outcome remains
unknown when the identity/effect proof cannot be established.

Queued promotion/replay keeps the admitted identity. Explicit retries cannot
silently change a retained lead identity. A yielded foreground request's identity
remains on its original admission. The existing TaskOwner admission guard checks
that canonical source, while subordinate continuation execution does not claim
foreground journal eligibility. Its existing grant/options/native-transfer proof
is preserved. No new executor, table, coordinator, resumption or replay is added.

## Limits

Registry data is a separate file, not part of the Gateway SQLite transaction.
Checks detect identity drift at dispatch, binding, settlement and recovery;
this does not claim cross-file transactional isolation. Tool authority remains
with the existing frozen grant and policy kernel. Identity proof is not a grant.
Unsupported attachments/options/background/specialist/framework/legacy lanes do
not gain sealed request recovery. No-role controls are distinct from real default
lead requests; a historical named lead cannot be promoted using its current role.

## Verification record

Deterministic tests exercise actual Gateway admission/producer/continuation,
TurnExecutive, effect ledger, TaskCards and sealed reconciliation with a scripted
model port. They cover pre-seal unknowns, sealed recovery without execution,
identity/route/grant/binding drift, queue/retry/yield, returned cancellation,
async cancellation and unresolved descendants.

Owned HTTP controls use the authenticated WebUI proxy and real resident/runtime,
with only the model provider scripted. They exercise home, explicit lead new-chat
and ordinary no-selector creation separately. Restart/replay checks count provider
calls and compare retained transcripts and full results. This is HTTP-level
integration, not browser, Mac-runtime or live-model acceptance.

Initial HTTP harness attempt used an unsupported `/api/jaeger/agents` URL and
returned 404 before execution. Corrected route is the actual `/v1/agents` proxy.
Initial focused regressions caught validation occurring after specialist setup,
and foreground identity leaking into exact durable-child admission shapes; both
were repaired at their producer boundaries, not by weakening the assertions.
The initial static create-handler inference missed `archive_on_create`, which
assigns the default lead. Full-handler tests are the source of truth.

Independent review additionally caught a duplicate registry key shadowing a
canonical disabled lead, and malformed registry-version parsing escaping the
dispatch fence. Read-only lookup now uses the exact validated persisted entry;
lookup parse failures become unavailable identity. Dispatch/seal/recovery tests
cover both, without changing ordinary catalog discovery or seeding behavior.

A further review exposed legitimate first-turn autorouting conflicting with a
premature lead marker. Route-eligible, unpinned first turns now keep their prior
execution and routing contract and receive no lead journal marker. Only existing
home/pinned/route_checked assignments qualify at admission. A non-matching first
turn commits route_checked through the existing router; later lead turns can
qualify. HTTP controls explicitly distinguish that initial exclusion from the
subsequent sealed request. A matching first-turn routing test uses the actual
create handler, registry and suggestion/router producer. Untouched baseline
specialist execution separately lacks bind_skill_scope; this increment does not
claim to repair that missing implementation.
