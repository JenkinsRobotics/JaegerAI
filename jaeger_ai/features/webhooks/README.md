# Webhook subscription proposals

Existing Gateway schema metadata owns local-operator subscription definitions; existing control-operation receipts, durable tasks and approvals own delivery dedupe/admission. No second queue, scheduler, credential store or execution runtime. New definitions save disabled, explicit event/sender filters and an existing bot conversation are required. Restore remains disabled. UI controls do not start the listener, provision credentials or publish an endpoint.

The existing loopback listener accepts `/hook/<subscription-id>` (or `/github/<id>`). Existing shared-secret bearer or exact SHA256 HMAC is required for admission. Shared-secret authentication is connection authentication, not independent upstream sender identity. Sender/event filters constrain authenticated data; incoming content never supplies authority, caller, tool grants, agent identity or workspace. Unscoped legacy requests are refused rather than automatically running turns or scheduling board cards.

One SQLite transaction inserts the subscription-scoped event receipt, paused durable task and one task approval. Duplicate identity returns the same receipt; changed content conflicts, even after denial/restart. No execution on ingress. Existing operator task approval authorizes only that task; all subsequent tool policies/approvals still apply. Subscription changes/revocation block new task dispatch; already admitted/unknown execution is retained without replay. Provider content is excluded from general delivery receipts/events; the approval/task contains explicitly labelled untrusted data for review. History is bounded to the latest100 receipts and preserves Gateway arrival order; no remote chronological-order guarantee is claimed.

Compatibility: additive metadata/provenance/receipts only, no schema migration. Historical webhook_deliveries.json and board cards are untouched and are not replayed/imported. Preserve the new code while pending subscription tasks exist; old runtimes do not understand revocation guards. No external activation or credential mutation is part of this implementation. Remote subscription provisioning and independent publisher authority remain unsupported.
