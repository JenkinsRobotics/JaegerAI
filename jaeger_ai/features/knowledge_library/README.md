# Knowledge Library

The active instance comes from the canonical `jaeger_agent.core.workspace.get_layout()` binding shared by Gateway and CLI; Library does not initialize or inspect a separate CLI pipeline.

One instance-owned SQLite `layout.memory_dir/library.db` serves both read-only indexed collections and app-owned managed documents. `store.py` indexes safe text files in already registered roots; it never writes those source files. `managed.py` stores native document content, optimistic revisions, immutable version snapshots and recoverable archive state in additive tables in that same database. Archived managed documents are excluded from ordinary search; restore preserves identity and versions. Restoring a prior version creates a new revision and cannot bypass an archive or revision conflict.

`tools.py` exposes the existing permission-gated collection add/index operations and read-only search/read tools. The Gateway library routes expose existing indexed content and managed document operations; reads use existing read scope, mutations require existing admin scope. No directory grants, credentials, recipient-access grants, public links or permanent deletion are added. Explicit saved-document export returns a revision/digest-checked literal JSON snapshot; it does not include renderer drafts, credentials, paths or access authority. The client rechecks the content digest before requesting a local download; OS save completion remains unconfirmed. Cross-account sharing requires a recipient authority contract that the single local operator system does not provide. Browser controls never accept a filesystem path.

Migration is additive (`library_managed_documents`, `library_document_versions`). Existing indexed corpus/FTS tables and external files remain intact. Older code can leave these tables in place during rollback; do not drop them or discard the renderer's pending operation IDs. No production database migration is performed by a source build.

Custom-specialist knowledge bindings pin managed document ID/revision/digest in the existing agent registry. Up to eight documents/32,000 characters; no indexed external source, tool grant or credential inheritance. Each executing turn loads the pinned immutable versions through the same Library owner, records metadata-only `agent.knowledge` context and shows the loaded titles/revisions in live and restored transcripts. Missing/archived/inconsistent assignments fail before model/tool execution. Updating a document does not silently replace a pinned revision; explicitly save bindings again to refresh versions. Removing a binding affects later execution, not already-loaded context. Session-prefixed outside callers do not acquire global library read through a specialist's assignment.

Compatibility: additive registry `knowledge_documents` metadata, existing shared configuration revision/CAS and existing library versions/activity history only. No new database schema/store; rollback preserves bindings, document versions and device selection/pending-save records. Prompt references are data and never approval/tool authority. Context is captured when execution starts, not frozen at initial queue admission; this timing is explicit and remains a qualification boundary.

Managed edits/archive/restore use `BEGIN IMMEDIATE` on the existing Library SQLite owner across revision comparison, changes, version insertion and the final server write-window check. Each in-flight command has a five-second monotonic validity window (from HTTP mutation entry, or owner call for internal users); expiry rolls back before commit, including FTS/version/tombstone changes. An expired command is a known rejection; it never renews/replays its original operation ID. A new reviewed command can be submitted explicitly. CAS plus this bounded write window is the local lease-equivalent, **not an exclusive editing lease, distributed lock or cross-principal permission**. Typing a local draft holds no lock and does not itself expire. Successful receipts use the snapshot captured inside their transaction, even if another connection commits before the caller returns. A subsequent newer read cannot silently replace or rebase the renderer draft.
