# --- framework + reusable mind (git dependencies — none of these have PyPI
# releases yet). PEP 508 direct references, not
# `-e ../X` — setuptools' dynamic-dependencies file parser only accepts
# requirement specifiers, not pip's `-e`/`-r` directives. A dev clone
# with sibling ~/GITHUB/{JaegerOS,jaeger-agent,JaegerKokoroTTS,
# JaegerWhisperSTT} checkouts gets editable installs of those instead —
# see install.sh's sibling-detection step. kokoro_tts + whisper_stt are
# DEFAULT deps (not optional extras) as of 0.9: a robot needs a voice out
# of the curl one-liner, not a follow-up install.
#
# ALL FOUR TRACK @master, and the 0.9.0 tag pins they replaced were
# actively wrong rather than merely stale. 0.10 is tested against
# jaeger-os 0.10.0, kokoro_tts 0.12.0, whisper_stt 2.0.0 and jaeger-agent
# 1.0.0; the only tag any of those repos has published is 0.9.0. A fresh
# clone pinned there installed engines OLDER than anything this release
# was tested with, and that is not a theoretical hazard — kokoro's config
# schema dropped `sample_rate` between 0.9 and 2.0, so the mismatch
# aborted boot with a pydantic extra_forbidden error rather than
# degrading. (jaeger-agent@v1 was worse: that branch does not exist on
# the remote at all, so the requirement could not resolve for anyone.)
#
# The voice packages publish an exact JaegerOS @0.9.0 direct reference, so the
# root must use that same reference for pip to resolve one framework. The tag
# resolves to commit 149de70b4e2289e01ef49407e4ae8c37a4b23185 at this release gate;
# the contract test locks both values. Remaining repositories use immutable
# commit references. install.sh must never force an incoherent runtime with
# --no-deps.
