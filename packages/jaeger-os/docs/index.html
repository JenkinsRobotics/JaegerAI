// what it is

Framework, not product. Pinned, never forked.

JaegerOS is the framework tier of the Jaeger ecosystem — like ROS is to a robot stack: libraries, standards, and tooling that other things build on, pinned to a release, never forked. It is deliberately useful without any AI — a robot body can boot, speak, listen, and move on JaegerOS alone.

JaegerOS does not ship a CLI, an agent loop, or an inference stack — that's JaegerAI's job. JaegerOS is a pinned dependency, not a product you run directly.

One copy of every truth: the wire contract lives in contract/, which imports nothing at all — CI-enforced. See CONVENTIONS.md for the full ecosystem ruleset.

// capabilities

What ships in the framework tier

Real, shipped capabilities — not aspirational ones. See CONVENTIONS.md → "No spec ahead of code."

Bus + Node

A four-phase Node lifecycle (setup → tick → teardown → health) over an in-process or ZMQ Bus — the same contract whether a module runs in-thread or on its own board.

transport

Modules & slots

discover_modules() resolves a slot (tts, stt, animation, messaging, mind, …) to whichever module.yaml wins — in-tree, or out-of-tree via the jaeger_os.module_roots entry-point group.

core

Capability layer

A hardware package declares capabilities: in its topology manifest; the framework materializes them into permission-tiered tools at boot — Mind and Body meet without either importing the other.

// roadmap

From the monorepo to a real ecosystem seam.

0.9.0 — In progress

The four-way split

contract/ landed as the one wire truth, the CI dependency rule enforced (runtime/hardware never import agent/), the Mind promoted to a module in-repo, then JaegerOS / JaegerAI / JaegerKokoroTTS / JaegerWhisperSTT filter-repo'd into their own history-preserving repos — six gates run, cross-install proven. 0.9.0 itself has not shipped yet.

0.9.x — Next

Out-of-tree JP01

The first external hardware package: jp01 loads from JP01_Firmware, not this repo. The capability layer's three remaining gaps close — a per-station supervised node, a per-unit verified flag, and a boot-time topology.yaml handshake.

Later

1.0 — the ecosystem opens

Contract freeze. Engine modules and hardware packages move to independently-versioned repos, ROS2-package-style, once the slot contracts survive a real body and a real engine swap.
